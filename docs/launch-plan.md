# Maintainer launch plan / 维护者发布方案

## Positioning

GitHub description suggestion:

> Microduck resources & practical guides: simulation, RL, ROS 2, MCP and DIY. 中英双语机器鸭入门、训练与硬件导航。

Suggested topics: `awesome`, `awesome-list`, `microduck`, `robotics`, `reinforcement-learning`, `mujoco`, `sim-to-real`, `ros2`, `embodied-ai`.

## Before publication

1. Create or select the intended GitHub repository and push this directory. There is no remote configured in the initial local deliverable.
2. Set the description and topics, enable Issues, and review the first CI run.
3. Decide on one real destination if you want product, newsletter or community traffic. Place a clearly labeled maintainer link below the homepage route table; disclose ownership. No external conversion destination was supplied during initial preparation.
4. Publish a first Release using the actual review notes; the homepage's Releases subscription then has a concrete first item.
5. Add this repository URL to your GitHub profile or existing relevant project documentation.

Append the real repository URL when publishing. This draft has not been sent anywhere. Share where project announcements are welcome; contribute to related lists only when this guide supplies useful additional material.

## Measure usefulness

Use GitHub's available traffic statistics and manual dated snapshots to record views, unique visitors, clones, referring sources, stars and substantive contributions. Record the same observation window when comparing periods. These signals do not establish a per-visitor conversion rate by themselves.

优先观察入门问题是否减少、用户是否提交复现记录、链接是否保持有效。若有自有网站，再按该网站的分析能力记录出站入口效果。持续发布实际更新，不承诺“每日更新”或虚构使用人数。
